# Absorbent

Превращает запись онлайн-лекции (скринкаст `*.mkv`/`*.mp4` или аудиофайл) в
качественный конспект в Markdown: структурированный текст по транскрипту,
иллюстрации из видео, а также материалы лектора — страницы презентации и
фотографии доски, формулы в LaTeX. Основной источник конспекта — речь
лектора: презентация обычно длиннее лекции, поэтому слайды, содержание
которых не прозвучало, в конспект не попадают, а материалы лишь уточняют и
поправляют сказанное. Готовый `notes.md` ложится в каталог, названный по
имени записи (`<имя>/` рядом с исходником), изображения — в его подкаталог
`images/`, документ можно сразу отдавать в pandoc.

## Быстрый старт

```bash
absorbent lecture.mkv                      # видео лекции целиком
absorbent lecture.m4a --slides deck.pdf    # аудио плюс колода лектора
absorbent lecture.mkv --flat               # результат рядом с записью
absorbent                                  # интерактивный мастер
```

Примеры ниже считают, что `absorbent` уже в PATH (см. «Установка из
исходников»). Из каталога репозитория ту же команду выполняет
`uv run absorbent`.

Конвейер устроен так:

1. из видео через ffmpeg извлекаются кадры с частотой `--fps` (по умолчанию
   один кадр в секунду); вход без видеопотока (аудиофайл) проверяется
   `ffprobe` и пропускает этот и следующий этап;
2. кадры отбираются по перцептивному хешу (pHash): сцена — отрезок подряд
   идущих кадров, каждый из которых не дальше `--hash-threshold` бит от
   первого кадра отрезка; из каждой сцены берётся ядро — кадр, ближайший к
   остальным её кадрам, а сцены короче `--min-scene-seconds` отбрасываются
   как анимация, промежуточные состояния и шум; похожие соседние ядра не
   дублируются. Если порог не прошла ни одна сцена, берётся ядро самого
   длинного отрезка, и конвейер печатает предупреждение «нет сцен длиной …
   с и более, взят самый длинный отрезок», — поэтому даже при большом
   `--min-scene-seconds` один кадр в конспекте остаётся;
3. материалы лектора задаются флагом `--slides`: презентация или документ
   (PDF, `.pptx`/`.odp`/`.docx`/…) растрируется в страницы с разрешением
   `--slides-dpi`
   (PDF разворачивается `pdftoppm` сразу, остальные форматы сначала
   конвертирует LibreOffice) и ложится в `images/slide_NNN.png`, а фотография
   доски (`.png`/`.jpg`/`.jpeg`/`.webp`) копируется как есть в
   `images/photo_NNN.<расширение>` — рядом с кадрами видео;
4. речь распознаётся в транскрипт с таймкодами: локально через Whisper или
   облачно через Voxtral (Mistral); разметку говорящих даёт только Voxtral —
   Whisper пишет речь без имён, поле `speaker` остаётся пустым. Метка
   говорящего сохраняется в `transcript.json`, а синтез получает её
   префиксом `[<speaker>]` в строке транскрипта, поэтому имена могут
   появляться и в конспекте;
5. vision-модель описывает каждый ключевой кадр, получая на вход картинку,
   её таймкод и фрагмент транскрипта ±60 секунд вокруг этого момента; страницы
   презентации и фотографии доски описываются теми же вызовами, но без
   транскрипта: у них нет таймкода, поэтому модель получает картинку, для
   страницы — её номер («слайд 3 из N», где N — общее число картинок
   материалов, включая фотографии доски: отдельного числа страниц колоды
   промпт не передаёт), и промпт своего вида: печатный слайд
   или рукописная запись на доске; ошибка API на отдельной картинке не
   прерывает прогон — в её описание попадает текст ошибки;
6. текстовая LLM синтезирует полный Markdown-конспект по транскрипту,
   описаниям кадров и материалам лектора. Транскрипт объявлен в промпте
   единственным источником того, что было на лекции, а слайды и фотографии
   доски — справочным материалом: раздел, тезис или иллюстрация по слайду,
   содержание которого не прозвучало, в конспект не попадает, а
   формулировки и формулы материала переносятся только туда, где речь
   действительно об этом говорит. Изображения вставляются ссылками
   `![подпись](images/frame_....jpg)`, `![Слайд N](images/slide_NNN.png)` и
   `![Фотография доски](images/photo_NNN.<расширение>)` ровно с теми именами
   файлов, что реально лежат на диске; пустой (или состоящий из пробелов)
   ответ модели считается ошибкой этапа: запрос повторяется один раз, а при
   повторной пустоте конвейер останавливается с диагностикой
   (`finish_reason`, расход токенов, длина reasoning) — пустой `notes.md` не
   записывается, HTML и PDF не собираются;
7. постпроцессинг: таблицы notes.md выравниваются скриптом
   `fmt-md-tables`, затем pandoc собирает самодостаточный `notes.html`
   (CSS-тема github-markdown, формулы MathML) и `notes.pdf` через движок
   lualatex со шрифтами DejaVu.

Провайдеры и модели задаются в одном YAML-файле; ключи API берутся из
переменных окружения; конкретная модель каждого этапа выбирается флагом
командной строки.

## Установка из исходников

Нужны [uv](https://docs.astral.sh/uv/), `ffmpeg` и `ffprobe` в PATH (пакет
`ffmpeg` в Arch Linux); сам пакет требует Python 3.13+ (uv поставит его сам).
CUDA-видеокарта необязательна — нужна только для локального Whisper; без неё
Whisper работает на CPU медленнее.

```bash
git clone git@gitlab.com:murtaught/absorbent.git
cd absorbent
uv sync
```

`uv sync` создаёт рядом с исходниками окружение `.venv` со всеми
зависимостями; первый `uv sync` идёт долго, потому что `torch` и
`openai-whisper` тянут за собой CUDA-библиотеки (несколько гигабайт). Запуск
прямо из репозитория — через `uv run`, без установки в PATH:

```bash
uv run absorbent lecture.mkv
```

Чтобы `absorbent` стал обычной командой в PATH (примеры в этом документе
рассчитывают на это), поставьте пакет инструментом uv:

```bash
uv tool install --editable .
```

`--editable` оставляет пакет связанным с исходниками, поэтому правки кода
подхватываются без переустановки; без него после правок нужно повторять
`uv tool install --force .`. `uv tool` ставит пакет в собственное окружение,
отдельное от `.venv`, и тянет те же зависимости; запускать
`uv tool install` нужно из каталога репозитория.

Конфигурация ищется в `./config.yaml`, затем в
`~/.config/absorbent/config.yaml` (см. «Конфигурация»). Рабочий `config.yaml`
лежит в репозитории, поэтому из его каталога настраивать ничего не нужно, а
для запуска из других мест скопируйте его:

```bash
mkdir -p ~/.config/absorbent
cp config.yaml ~/.config/absorbent/config.yaml
```

При первом запуске конвейера локальный Whisper скачивает веса модели в кэш
`~/.cache/whisper` (для `turbo` — файл `large-v3-turbo.pt` примерно на
1.6 ГБ).

Для постпроцессинга (этап 7) нужны внешние инструменты: `fmt-md-tables`,
`pandoc` (сам он собирает `notes.html`, а для `notes.pdf` вызывает движок
`lualatex`) и шрифты DejaVu (кириллица) — они нужны только PDF.
`fmt-md-tables` — скрипт автора проекта, в репозиторий не
входит; absorbent зовёт его как `fmt-md-tables --no-backup <notes.md>` и
ждёт выравнивания pipe-таблиц в файле на месте с кодом возврата 0, так что
своя замена должна поддерживать эти аргументы. Если подходящего скрипта нет,
отключайте постпроцессинг флагом `--skip-render`. `--skip-render` нужен и без
`pandoc` с `lualatex` — тогда конвейер останавливается на готовом `notes.md`.

Для презентаций (этап 3) нужны `pdftoppm` (пакет `poppler`) и — только для
не-PDF (`*.pptx`, `.odp`, …) — `soffice` (LibreOffice). Без них `--slides` с
колодой не работает, но конвейер без материалов от них не зависит, а
фотографии доски внешних программ не требуют вовсе.

## Конфигурация

Конфигурация ищется в порядке: путь из `--config` → `./config.yaml` →
`~/.config/absorbent/config.yaml`. В репозитории лежит рабочий `config.yaml`
со схемой (ниже — сокращённый фрагмент: в рабочем файле перечислено больше
моделей, но структура та же; комментарии в листинге добавлены для читателя —
в самом `config.yaml` их почти нет):

```yaml
providers:
  deepseek:                # OpenAI-совместимый провайдер
    base_url: https://api.deepseek.com
    api_key_env: DEEPSEEK_API_KEY   # имя переменной окружения с ключом
  llama-swap:              # локальный сервер (llama-swap на 127.0.0.1:12434)
    base_url: http://127.0.0.1:12434/v1
    api_key_env: ""        # ключ не запрашивается: клиенту уходит заглушка
  mistral:                 # облако Mistral, нужен MISTRAL_API_KEY
    base_url: https://api.mistral.ai/v1
    api_key_env: MISTRAL_API_KEY

stt:                       # распознавание речи
  whisper-turbo:           # локальный Whisper (по умолчанию)
    backend: whisper
    whisper_model: turbo
    default: true
  voxtral-transcribe-2:    # облачный Voxtral (Mistral), нужен MISTRAL_API_KEY
    backend: voxtral
    provider: mistral
    model: voxtral-mini-latest

vision:                    # описание кадров
  deepseek-v4-flash-vision-exp:
    provider: deepseek
    default: true

llm:                       # синтез конспекта
  deepseek-v4-flash:
    provider: deepseek
    default: true
```

Правила:

- `default: true` ровно в одной модели каждой категории (`stt`, `vision`,
  `llm`) задаёт модель по умолчанию;
- ключ API провайдера читается из переменной окружения, имя которой
  указано в `api_key_env`; если переменная названа в конфиге, но в
  окружении её нет, программа останавливается с ошибкой
  `missing env var <имя>` — это ошибка этапа (код завершения 1, сообщение
  `ошибка обработки <файл>: missing env var <имя>`), а не ошибка
  конфигурации;
- пустое `api_key_env` — провайдер без ключа: клиенту уходит заглушка
  (`not-needed`), поэтому локальному серверу (`llama-swap`) никаких
  переменных окружения не нужно. `OPENAI_API_KEY` absorbent не читает
  вовсе; заголовок `Authorization` с заглушкой сервер всё равно получает,
  но ни один настоящий ключ в него не подставляется;
- у моделей `stt` с `backend: whisper` поле `whisper_model` задаёт модель
  openai-whisper; у облачных бэкендов поле `model` — id модели в API, а если
  оно не задано, в API уходит имя ключа секции (`deepseek-v4-flash` для такой
  записи выше);
- запросы к облачным провайдерам идут через `httpx`, поэтому
  `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` из окружения (в том числе
  `socks5://` — для SOCKS в зависимостях стоит `socksio`) учитываются
  автоматически, без отдельных флагов.

Необходимые переменные окружения:

- `DEEPSEEK_API_KEY` — для облачных моделей DeepSeek (vision/llm по
  умолчанию);
- `MISTRAL_API_KEY` — только если выбран `--stt voxtral-transcribe-2`.

Локальный Whisper (`--stt whisper-turbo`, по умолчанию) работает без OpenAI
SDK, поэтому для прогона на нём достаточно `DEEPSEEK_API_KEY`; облачный
Voxtral собран на клиенте OpenAI SDK и требует `MISTRAL_API_KEY`.

## Использование

```bash
absorbent lecture.mkv
```

Из каталога репозитория без установки в PATH `absorbent` заменяется на
`uv run absorbent`.

Флаги:

| Флаг                        | Значение по умолчанию         | Описание                                                                                                                                                                                                                                    |
|-----------------------------|-------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `input`                     | —                             | путь к медиафайлу или директории (обрабатываются все файлы `.mp4 .mkv .webm .avi .mov .mp3 .wav .flac .ogg .m4a .opus`); без аргументов запускается мастер                                                                                  |
| `--config PATH`             | поиск по умолчанию            | путь к YAML-конфигурации                                                                                                                                                                                                                    |
| `--stt NAME`                | дефолт из конфига             | модель распознавания речи                                                                                                                                                                                                                   |
| `--vision-model NAME`       | дефолт из конфига             | модель описания кадров                                                                                                                                                                                                                      |
| `--llm-model NAME`          | дефолт из конфига             | модель синтеза конспекта                                                                                                                                                                                                                    |
| `--language {ru,en,auto}`   | `auto`                        | подсказка языка распознавания речи; `ru/en` форсируют весь файл как один язык, `auto` — детекция (для двуязычных лекций всегда `auto`)                                                                                                      |
| `--output-language {ru,en}` | `ru`                          | язык итогового конспекта и промптов; дословные RU/EN-фразы лекции сохраняются в оригинале                                                                                                                                                   |
| `--fps N`                   | `1`                           | частота извлечения кадров                                                                                                                                                                                                                   |
| `--hash-threshold N`        | `10`                          | порог pHash-расстояния в битах: граница сцены и отсев похожих ядер, 0–64                                                                                                                                                                    |
| `--min-scene-seconds S`     | `5`                           | минимальная длительность сцены, с: короче — анимация или промежуточное состояние (`0` — отключить отсев коротких сцен)                                                                                                                      |
| `--slides PATH`             | —                             | материал к лекции: презентация или документ (PDF, `.pptx`/`.ppt`/`.odp`/`.key`/`.docx`/`.doc`/`.odt`; конвертируется LibreOffice) либо фотография доски (`.png`/`.jpg`/`.jpeg`/`.webp`); можно указать каталог с ними; флаг можно повторять |
| `--slides-dpi N`            | `150`                         | разрешение растеризации страниц презентации (на фотографии не влияет)                                                                                                                                                                       |
| `--output-dir DIR`          | `<имя_файла>/` рядом с входом | каталог результата                                                                                                                                                                                                                          |
| `--flat`                    | —                             | результат и сырой транскрипт рядом с входным файлом (`<имя>.md`, `<имя>.json`, `<имя>.images/`), кэш — в `<каталог>/.absorbent/<имя>/`                                                                                                      |
| `--force`                   | —                             | игнорировать кэш и перезапустить все этапы, включая синтез и постпроцессинг                                                                                                                                                                 |
| `--skip-render`             | —                             | пропустить постпроцессинг (таблицы, HTML, PDF)                                                                                                                                                                                              |

Неизвестное имя модели (`--stt`, `--vision-model`, `--llm-model`) печатает
список допустимых имён в этой категории и завершается с кодом 2.

### Несколько записей и коды завершения

Если на вход подан каталог, обрабатываются все найденные в нём медиафайлы
(список расширений — в описании флага `input`), по одному за прогон. Ошибка
на одном файле печатается в stderr и не прерывает остальные: конвейер идёт
до конца каталога, а имя файла в сообщении указывает, где именно он упал.

Коды завершения:

| Код | Когда                                                                                                                                                                                                                                                                                                                                                                                       |
|-----|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 0   | все записи обработаны                                                                                                                                                                                                                                                                                                                                                                       |
| 1   | этап завершился ошибкой (в том числе `missing env var …`); при входе-каталоге остальные записи всё равно обрабатываются                                                                                                                                                                                                                                                                     |
| 2   | ошибка, найденная до запуска конвейера: неизвестная модель, несуществующий входной путь, каталог без медиафайлов, неверный путь в `--slides` или каталог без материалов, отсутствующий файл конфигурации, мастер запущен без терминала; ошибки конфигурации и материалов печатаются как `ошибка: <текст>`, а мастер без терминала — сообщением argparse (`usage: …`, `absorbent: error: …`) |
| 130 | интерактивный мастер отменён (Esc или Ctrl-C), обработка не начиналась                                                                                                                                                                                                                                                                                                                      |

Язык лекции и язык конспекта — независимые настройки. Лекции могут быть
двуязычными (например, речь почти целиком на английском с русскими
вставками): whisper возвращает один язык на весь файл, поэтому для таких
записей `--language` следует оставлять в `auto`. `--output-language`
определяет, на каком языке модель пишет описания кадров и конспект, а
дословные фразы и термины из транскрипта на другом языке (например,
русские цитаты в английской лекции) сохраняются в оригинале.

Если кадров вышло слишком много или слишком мало — перенастройте
`--min-scene-seconds` (для быстрой смены картинки на демонстрации экрана —
`2`, а `0` отключает отсев коротких сцен: ядро берётся из каждого отрезка,
и лишь совсем похожие соседние ядра всё равно отбрасываются; для слайдов с
анимацией — больше), `--hash-threshold` (меньше — больше
сцен) или `--fps`. Кадры кэшируются, повторный прогон без `--force` не
переизвлекает видео и не повторяет отбор ключевых кадров, поэтому новые
`--fps`, `--hash-threshold` и `--min-scene-seconds` применяются только с
`--force` (или после удаления `.absorbent/`); без них отбор заново идёт лишь
при отсутствии `keyframes.json`. Без `--force` синтез не пересобирается —
готовый `notes.md` остаётся как есть, — а HTML и PDF не пересобираются, пока
не станут старше `notes.md` (правка конспекта руками их обновляет, см. «Кэш
этапов»). `--force` перезапускает и синтез с постпроцессингом (LLM
вызывается заново), а заодно приводит `images/` и описания к текущему набору
кадров.

### Материалы лектора: презентации и фотографии доски

Материалы к лекции конвейер не ищет сам: путь задаётся флагом `--slides` (его
можно повторять, можно указать каталог — тогда берутся все файлы с
расширениями презентаций и документов: `.pdf`, `.pptx`, `.ppt`, `.odp`,
`.key`, `.docx`, `.doc`, `.odt` — и изображений: `.png`, `.jpg`, `.jpeg`,
`.webp`):

```bash
absorbent lecture.m4a --slides deck.pdf
absorbent lecture.m4a --slides доска.jpg
```

Ни флаг `--slides`, ни конвейер не ищут материалы по имени записи: в плоском
режиме absorbent сам пишет рядом с записью `<имя>.pdf` (конспект прошлого
прогона), и такой файл был бы принят за презентацию. Мастер заранее отмечает
в списке одноимённый файл, но отметку видно в диалоге, и её можно снять (см.
«Мастер»).

Презентация растрируется постранично (PDF — сразу `pdftoppm`, офисные
форматы — сначала LibreOffice), страницы описываются по одной (отсева почти
одинаковых соседних страниц пока нет) и попадают в конспект с меткой
«слайд N». Фотография доски — тот же материал: она копируется без конвертации
в `images/photo_NNN.<расширение>`, описывается промптом для рукописной записи
(формулы, схемы, неразборчивые места) и вставляется в конспект подписью
«Фотография доски». Нумерация страниц сквозная в порядке аргументов
`--slides`: и `slide_NNN.png`, и метка «слайд N» в конспекте считают страницы
по всем колодам подряд, номер страницы внутри своей колоды в конспект не
попадает. Номера у фотографий свои: фотография доски не сдвигает
нумерацию слайдов.

Ключевое правило конвейера: **конспект строится по речи, а материалы — только
справочник.** Материалы уходят в тот же вход синтеза, что и кадры: страницы
презентации — разделом «Слайды презентации» с пометкой «справочно: часть
колоды могла остаться за рамками лекции», фотографии доски — отдельным
разделом без неё. Промпт запрещает заводить раздел, тезис или иллюстрацию по
слайду, содержание которого не прозвучало в транскрипте. Так, если колода из
42 страниц разобрана на лекции до 15-й, по страницам 16–42 в конспекте не
будет ни одного раздела и ни одной ссылки — это следствие промпта, а не
замер (числа условные; артефактов такого прогона в репозитории нет). Сколько
именно разобранных страниц станут иллюстрациями, решает модель по содержанию
речи. Если транскрипт пуст (в записи нет речи или аудиодорожки), синтез всё
равно выполняется: в промпт вместо транскрипта уходит маркер
`(transcript unavailable)`, и конспект строится по одним материалам — режим
вырожденный, ход лекции он не восстанавливает.

Разрешение растеризации меняет `--slides-dpi` (по умолчанию 150; на
фотографии доски не влияет). Материалы готовятся только по флагу `--slides`: без него описаний
страниц в синтезе не будет, даже если прошлый прогон их оставил в кэше —
в синтез уходят описания только того набора картинок, что подготовлен в этом
прогоне.

Материалы можно давать и к аудиозаписи без видеопотока: тогда в `images/`
лежат только `slide_NNN.png` и `photo_NNN.<расширение>`, а каталогов кадров не
появляется. Страницы кэшируются в `.absorbent/slides/` и принимаются по
подписи источника: правка колоды, замена фотографии доски или смена
`--slides-dpi`
заставляют подготовить материал заново.

## Мастер

Вызов без аргументов запускает интерактивный мастер:

```bash
absorbent
```

Мастер обрабатывает одну запись за раз и последовательно спрашивает:
медиафайл (список медиафайлов текущего каталога, пункт «Другой каталог…» или
ручной путь — поэтому запись может лежать где угодно), материалы к лекции —
презентации и фотографии доски (отметки в списке с автоподсказкой одноимённого
файла, «Добавить материалы из другого каталога…» и ручной путь), раскладку
(`--flat` или каталог `<имя>/`), язык конспекта и модель синтеза. По желанию
открывается блок «дополнительно»: язык и модель распознавания речи, модель
описания, `--fps`, `--hash-threshold`, `--min-scene-seconds`, `--slides-dpi`,
`--force` и `--skip-render`.

Перед запуском печатается сводка «Команда: absorbent …» — её можно
скопировать в терминал и повторить прогон без диалогов. Клавиши в диалогах:
Enter подтверждает выбор в списке одиночного выбора и ввод в поле; в списке
отметок материалов и Enter, и пробел переключают отметку, а подтверждают
отмеченное Esc или кнопка «Готово». Esc отменяет шаг в списках одиночного
выбора и в полях ввода, а в диалогах «да/нет» не делает ничего. Отмена
любого шага, как и Ctrl-C, прекращает прогон целиком («отменено», код 130):
вернуться к предыдущему шагу мастер не даёт. Отмена и отказ на последнем
подтверждении тоже ничего не запускают. Без терминала (например, из скрипта)
мастер не запускается: absorbent печатает ошибку и возвращает код 2, а не
зависает на вводе.

Обёртка `~/.local/bin/transcribe` — личный скрипт автора, в репозиторий не
входит. Она делегирует запуск absorbent'у в плоском режиме (`--flat`),
поэтому годится для быстрого прогона из каталога с записями; дополнительные
флаги она пробрасывает, так что материалы можно указать и через неё:

```bash
transcribe lecture.m4a --slides deck.pdf
```

## Выходные файлы

Для входа `Lecture.mkv` (каталог результата по умолчанию — `Lecture/`):

```
Lecture/
  notes.md                  # итоговый конспект Markdown
  notes.html                # самодостаточный HTML (css и кадры встроены)
  notes.pdf                 # PDF через lualatex
  images/                   # весь подготовленный набор картинок
    frame_HH_MM_SS.jpg      # отобранные ядра видео
    slide_NNN.png           # страницы презентации из --slides
    photo_NNN.jpg           # фотографии доски из --slides
  .absorbent/               # кэш промежуточных результатов
    transcript.json         # [{start, end, text, speaker}]
    audio.wav               # извлечённое аудио (только voxtral)
    language.txt            # детектированный язык
    frames/                 # все извлечённые кадры до отбора ключевых кадров
    keyframes.json          # отобранные кадры: image/seconds/timestamp
    descriptions.json       # описания кадров vision-моделью
    slides/                 # на источник (slides/<NN>_<имя>/): страницы,
                            # фотографии доски, PDF конвертации (не-PDF),
                            # signature.json
    slide_descriptions.json # описания страниц презентации и фотографий доски
```

`notes.md`, `notes.html`, `notes.pdf` и `images/` — результат; всё под
`.absorbent/` можно удалять без потери результата (кэш лишь ускоряет
повторные прогоны). `images/` содержит весь подготовленный набор, а не только
картинки, на которые ссылается `notes.md`: страницы, чей слайд не прозвучал,
тоже туда попадают. Каталог `images/` и кэшевый `frames/` появляются только у
входа с видеопотоком: аудиофайл без материалов их не создаёт. С `--slides` у
аудиовхода появляется один `images/` — только с материалами лектора, без
кадров. В плоском режиме этим каталогам соответствуют `<имя>.images/` и
`<каталог входа>/.absorbent/<имя>/frames/`.

### Плоский режим (--flat)

Флаг `--flat` кладёт результат рядом с медиафайлом, без каталога `<имя>/`:

```
Lecture.mp4
Lecture.md                  # итоговый конспект Markdown
Lecture.json                # сырой транскрипт [{start, end, text, speaker}]
Lecture.html                # самодостаточный HTML
Lecture.pdf                 # PDF через lualatex
Lecture.images/             # весь подготовленный набор картинок
  frame_HH_MM_SS.jpg        # отобранные ядра видео
  slide_NNN.png             # страницы презентации
  photo_NNN.jpg             # фотографии доски
.absorbent/
  Lecture/                  # кэш промежуточных результатов
    language.txt
    audio.wav               # извлечённое аудио (только voxtral)
    frames/
    keyframes.json
    descriptions.json
    slides/
    slide_descriptions.json
```

Ссылки на изображения в конспекте получают префикс `<имя>.images/`, поэтому
относительные пути остаются корректными; `--output-dir` и в этом режиме
задаёт каталог результата, а кэш всё равно ложится в
`<каталог входа>/.absorbent/<имя>/`.

### Кэш этапов

Признак готового этапа — его артефакт: `transcript.json` (распознавание),
`keyframes.json` (отбор кадров), `descriptions.json` (описание кадров),
`slide_descriptions.json` (описание страниц и фотографий), `notes.md` (синтез).
Материалы принимаются по подписи источника в `.absorbent/slides/<NN>_<имя>/`
(канонический путь, размер, mtime и `--slides-dpi`), где `NN` — позиция
источника в `--slides`: правка колоды или замена фотографии подпись меняет и
готовит материал заново, а добавление или перестановка материала сдвигает
позиции и пересобирает и соседей. Повторный прогон без `--force`
переиспользует готовые артефакты: `notes.md` не пересобирается, а LLM не
вызывается вовсе.
Постпроцессинг пропускается, когда `notes.html` и `notes.pdf` не старше
`notes.md`, — правка конспекта руками заставляет пересобрать обе версии.

Полный перезапуск — `--force`. Он же нужен, когда готовый результат больше
не соответствует настройкам: например, после смены `--output-language`,
`--llm-model` или набора `--slides` (`notes.md` переиспользуется как есть,
язык промпта синтеза в нём не записан).

Пересобрать один этап, не трогая остальные, — удалить его артефакт. Для входа
`Lecture.mkv` в раскладке `<имя>/` это `Lecture/.absorbent/keyframes.json`
(повторит отбор ключевых кадров) и `Lecture/notes.md` (повторит синтез:
транскрипт, кадры и описания возьмутся из кэша), а `touch Lecture/notes.md`
заново соберёт HTML и PDF. В плоском режиме кэш лежит в
`<каталог входа>/.absorbent/<имя>/`, а конспект — `<имя>.md` рядом с записью.

### Вход без видеопотока

Если во входном файле нет видеопотока (mp3, m4a, wav), этапы извлечения и
отбора ключевых кадров пропускаются: конвейер печатает «кадров нет (аудио без
видеопотока)» и собирает конспект только по транскрипту, без иллюстраций.
Проверка выполняется `ffprobe` до запуска ffmpeg, поэтому аудиофайл не
завершается ошибкой извлечения кадров, а каталогов кадров (`images/` и
кэшевого `frames/`) не появляется вовсе. С `--slides` каталог `images/`
появляется, но содержит только материалы к лекции — страницы презентации и
фотографии доски; часто именно так и работают с записью голоса и отдельной
колодой.

## Постпроцессинг

После синтеза конвейер автоматически:
1. выравнивает таблицы `notes.md` внешним скриптом `fmt-md-tables`;
2. собирает самодостаточный `notes.html` через
   `pandoc --standalone --embed-resources` — CSS-тема github-markdown
   (файл в `src/absorbent/assets/github-markdown.css`, лицензия MIT,
   sindresorhus), изображения встроены как data-URI, формулы — MathML;
3. собирает `notes.pdf` через `pandoc --pdf-engine=lualatex` со шрифтами
   DejaVu; первый заголовок notes.md становится title.

Обе версии наследуют от шаблонов pandoc дефекты вёрстки, поэтому при сборке
pandoc получает свои правки: HTML — CSS и контейнеры ключами `-H`, `-B` и `-A`
(`render._page_css()`, `render._html_parts()`, файлы временные), PDF —
преамбулу `render._LATEX_HEADER` ключом `-H`. Рядом с `notes.html` и
`notes.pdf` никаких файлов при этом не появляется.

HTML (`render._page_css`):
- фон `html` берётся из того же github-markdown.css, что и тема конспекта:
  без этого штатный белый фон даёт белые поля вокруг тёмной полосы текста;
- штатное ограничение полосы `body { max-width: 36em }` снимается правилом
  `html, body { max-width: none }`; ширину полосы задаёт `.page-inner` с
  `max-width: HTML_COLUMN_PX` (1280 px), а `padding` блока
  `.markdown-body.page` задан как `2.5rem clamp(1rem, 4vw, 4rem) 6rem`; при
  ширине экрана 767 px и меньше медиазапрос заменяет его целиком на
  `1.25rem 1rem 4rem` (и вертикальные поля, и боковые);
- первый заголовок остаётся в теле видимым `h1`, а не только в `<title>`.

PDF (`render._LATEX_HEADER`, `render.PDF_GEOMETRY`, A4 с полями 1.8 см):
- плавучие `figure` заменяются на неразрывные врезки: LaTeX ставил рисунок
  туда, где он не помещался, и низ страницы обрезался;
- язык конспекта (`--output-language`) передаётся в babel, включая правила
  переноса и подписи «Рис. N»; без них длинные слова вылезали за поля.

HTML/PDF можно отключить флагом `--skip-render` (например, когда pandoc
или lualatex не установлены).

## Разработка

- Код — Python 3.13+, пакет в `src/absorbent/`, каждый этап — отдельный
  модуль (`extract.py`, `dedup.py`, `transcribe.py`, `describe.py`,
  `slides.py`, `synthesize.py`, `render.py`), оркестрация — в `pipeline.py`,
  интерактивный мастер — в `wizard.py`.
- Соглашения по комментариям и коммитам — в `AGENTS.md`.
- Отложенные идеи — в `BACKLOG.md`.
- Сравнение бэкендов распознавания речи с замерами (WER, CER, скорость) —
  в `STT_COMPARISON.md`.
- Тесты: `uv run pytest --cov` (покрытие ветвей 100%, порог задан в
  `pyproject.toml` через `fail_under = 100`). Интеграционные тесты требуют
  ffmpeg/ffprobe и pdftoppm в PATH и пропускаются без них.
